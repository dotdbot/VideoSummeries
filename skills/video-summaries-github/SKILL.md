# Video Summaries → GitHub Pipeline

## Trigger
Any YouTube URL shared in the **"Youtubes" Telegram group** by Dotan.
Also triggered if the user explicitly asks to summarize a video.

---

```
REPO:       dotdbot/VideoSummeries
LOCAL_REPO: /tmp/vs_git
GIT_REMOTE: https://github.com/dotdbot/VideoSummeries.git
PAGES_URL:  https://dotdbot.github.io/VideoSummeries/
PAT:        read from ~/.git-credentials (grep dotdbot | grep -o 'ghp_[^@]*')
```

Ensure local clone is fresh:
```bash
if [ ! -d /tmp/vs_git/.git ]; then
  git clone https://github.com/dotdbot/VideoSummeries.git /tmp/vs_git
```

## Step 1 – Fetch Transcript

**CRITICAL: Always verify the video title first** before using any cached audio files:
```bash
python3.11 -m yt_dlp --get-title 'URL'
```
This prevents summarizing the wrong video from a stale `/tmp/ytaudio.mp3` cache. If title doesn't match, delete cached files and re-download.

Use the `youtube-content` skill helper script first:
```bash
python3 ~/.hermes/skills/media/youtube-content/scripts/fetch_transcript.py "URL" --text-only
```

**If it fails** (Hebrew/no transcript): fall back to kome.ai browser tool, then yt-dlp + faster-whisper.
See `youtube-content` skill for full fallback chain.

Detect language from transcript content. Respond in that language.

---

## Step 2 – Analyze & Summarize

From the transcript, extract:
- **Facts**: concrete data, numbers, names, events mentioned
- **Conclusions**: what the speaker concludes / believes
- **Recommendations**: actionable advice given
- **Stocks** (if finance video): ticker, opinion, price target, sentiment tag
- **Portfolio** (if shown): holdings + daily gains
- **Key quotes** (if interview/talk)

Also extract metadata:
- Video title (from yt-dlp or transcript opener)
- Channel/speaker name
- Duration
- Language (he/en/other)
- Category: Stocks | Business | AI | Interview | Other

## Step 2.5 – Save Transcript to Repo

Before building the HTML, save the transcript to the repo so the page can link to it:
```bash
mkdir -p /tmp/vs_git/summaries/transcripts
cp /tmp/transcript.txt /tmp/vs_git/summaries/transcripts/SLUG.txt
# Or fetch directly:
python3 SKILL_DIR/scripts/fetch_transcript.py "URL" --text-only 2>/dev/null > /tmp/vs_git/summaries/transcripts/SLUG.txt
```
The slug should be the same as the HTML filename slug (e.g. `twitter-x-20-accounts`).

## Step 3 – Generate HTML File

**Start from the template:** `templates/summary-page.html` — copy and fill in. Do not write from scratch each time.

**Filename format:** `YYYY-MM-DD_slug.html` (e.g. `2026-08-14_hebrew-stocks-daily.html`)
**Save to:** `/tmp/vs_git/summaries/`

### HTML Template Structure

Use dark GitHub-style theme (matches existing pages). Copy the CSS variables from existing pages:
```css
--bg: #0d1117; --surface: #161b22; --surface2: #21262d;
--border: #30363d; --accent: #58a6ff; --green: #3fb950;
--yellow: #d29922; --red: #f85149; --text: #e6edf3; --muted: #8b949e;
```

**Required sections in every page:**
1. `← Back to all summaries` link → `../index.html`
2. Header: badges (language + category), title, meta (date, duration, channel), YouTube link
3. Embedded YouTube player (`<iframe>` with video ID)
4. TL;DR box (1-3 sentences)
5. Content cards (Facts / Conclusions / Recommendations) — adapt to video type:
   - Finance: stock table with ticker/opinion/target/tag columns
   - Interview: key quotes + action steps
   - General: bullet facts + conclusions
6. Footer: "Generated by Dot DiBot · DATE" + YouTube link + transcript link
7. **Transcript link in the page**: always include a link to the raw transcript. Save the transcript text to `/tmp/vs_git/summaries/transcripts/SLUG.txt` before committing. Add a visible button/link near the YouTube link in the header: `📄 Full Transcript` → linking to `../summaries/transcripts/SLUG.txt` (relative) or the raw GitHub URL.
8. Always include both scripts before `</body>`:
   ```html
   <script src="../protect.js"></script>
   <script src="../copy-btn.js"></script>
   ```
   The copy button (📋 Copy post) is a fixed bottom-right floating button that copies all page text (no URLs, no nav links) to clipboard.

**Additional badge classes used in practice:**
- `badge-biz` → Business/general (`background: #1a2744; color: var(--accent)`)
- `badge-interview` → Interviews (`background: #1a2744; color: var(--accent)`)

**Always clone fresh if `/tmp/vs_git` doesn't exist, then pull before editing:**
```bash
if [ ! -d /tmp/vs_git/.git ]; then
  git clone https://github.com/dotdbot/VideoSummeries.git /tmp/vs_git

```

Then commit and push:
```bash
cd /tmp/vs_git
git config user.email "dotan.dicastro.b@gmail.com"
git config user.name "Dot DiBot"
git add -A
git commit -m "Add summary: VIDEO_TITLE (DATE)"
git push origin main
```

**If push fails with "Invalid username or token"** — the default git credential helper may not work. Fix with:
```bash
PAT=$(grep dotdbot ~/.git-credentials | grep -o 'ghp_[^@]*')
git remote set-url origin "https://dotdbot:${PAT}@github.com/dotdbot/VideoSummeries.git"
git push origin main
```

**Do NOT use curl API to push files** — base64 encoding large HTML files via the REST API is unreliable and slow. Always use git clone + push.

## Pitfalls

- **protect.js**: NEVER forget `<script src="../protect.js"></script>` before `</body>` in every summary page. Password = `Shira100`.
- **Transcript directory**: save transcript to `/tmp/vs_git/summaries/transcripts/SLUG.txt` — the `transcripts/` subdir must be created with `mkdir -p`. It is NOT created automatically by git.
- **Wrong video from cache**: always run `python3.11 -m yt_dlp --get-title URL` BEFORE doing anything with audio. If `/tmp/ytaudio.mp3` exists from a previous session, it may be a completely different video. Delete and re-download if title doesn't match.
- **yt-dlp 403 on audio**: if `android_vr` client fails with HTTP 403, run `yt-dlp -F URL` to list formats, then download the m4a directly with `-f 140 -o '/tmp/ytaudio2.m4a'` and convert: `ffmpeg -i /tmp/ytaudio2.m4a /tmp/ytaudio2.mp3 -y -loglevel quiet`.
- **badge-biz CSS**: the `badge-biz` class is not in the default CSS of older pages. Either add it explicitly in the `<style>` block (`background: #1a2744; color: #79c0ff`) or use `badge-en` / `badge-interview` as fallbacks.
- **Stats update**: find `<div class="val">N</div><div class="lbl">Videos Summarized</div>` and increment N. Use patch tool's exact string match — it's inside a `.stat` div.
- **Hebrew videos**: youtube-transcript-api often returns "No transcript found" — go straight to kome.ai, then whisper if kome fails.
- **Slug**: lowercase, hyphens only, max 40 chars. Strip Hebrew characters from slug (use English description).
- **Local repo stale**: always `git pull` before making changes to avoid conflicts.
- **Long transcripts (>50K chars)**: chunk and summarize each chunk before merging.
- **Git remote auth**: credentials are stored in `~/.git-credentials` — use them via remote URL, not PAT injection in code.
- **Stale cached audio (CRITICAL)**: yt-dlp skips download if `/tmp/ytaudio.mp3` already exists from a prior session and prints `[download] /tmp/ytaudio.mp3 has already been downloaded`. You will silently transcribe the WRONG video. Always delete stale files first: `rm -f /tmp/ytaudio.mp3 /tmp/chunk*.mp3 /tmp/transcript.txt`. Verify the title matches before transcribing: `python3.11 -m yt_dlp --get-title URL`.
- **transcripts/ directory**: always `mkdir -p /tmp/vs_git/summaries/transcripts/` before copying — this dir does not exist by default in the repo.
- **badge-biz class**: use for non-finance content (guides, interviews, tools). CSS: `background:#1a2744; color:#79c0ff`. Add inline to the page `<style>` if not in the template.
- **index.html multi-match on grid**: `<div class="grid">` appears multiple times. Always include the next `<a class="card"` with its href in old_string to make the patch unique.
- **curl API push (AVOID)**: pushing HTML files via GitHub REST API (`PUT /contents`) with base64 encoding is unreliable for large files and fails with "Bad credentials" even when the PAT is valid. Always use `git clone + push`.
- **yt-dlp 403 fallback for specific videos**: Some videos return HTTP 403 with the default android_vr client. Try `-f 140` (m4a audio format) directly when the default `-x --audio-format mp3` fails, then convert with `ffmpeg -i /tmp/ytaudio.m4a /tmp/ytaudio.mp3 -y`.
- **Transcript file naming**: Always save transcript to `/tmp/vs_git/summaries/transcripts/<slug>.txt` in the repo (create the dir with `mkdir -p` if it doesn't exist). The slug must match the HTML filename slug.
- **index.html stats div formatting**: the stats counter div after a patch may lose the outer `.stat` wrapper. The exact format in the file is `<div class="val">N</div><div class="lbl">Videos Summarized</div>` (no wrapping `.stat` div after the first patch). Use this exact string for future patches.
- **Video ID lookup**: if no YouTube URL is given but a title is provided, use `delegate_task` with web search to find the video ID before building the page.
- **"Copy the video and summary" requests**: user means "take the summary I already gave in my message and turn it into an HTML page + push to GitHub" — do NOT re-fetch the transcript. Use the provided summary content directly.
- **kome.ai preview is always truncated**: clicking "Get Transcript — Free" may not expand it fully in the snapshot. Always check `browser_console(expression="document.body.innerText")` after clicking — the full transcript appears between "Transcript (XXm XXs)\nCOPY" and "Why Use YouTube..." footer.
- **faster-whisper numpy conflict**: the `/tmp/whisper_venv` may have numpy 2.x which breaks ctranslate2. Use `uv run --with "faster-whisper" --with "numpy<2"` instead of the venv directly. Also set `KMP_DUPLICATE_LIB_OK=TRUE` env var on macOS to avoid OpenMP crash.
- **faster-whisper timeout**: 19-min audio in 2 chunks takes ~15 min on CPU. Always run as `terminal(background=True, notify_on_complete=True)` and poll with `wc -c /tmp/transcript.txt`.
- **CRITICAL — stale audio cache**: `/tmp/ytaudio.mp3` and `/tmp/transcript.txt` persist between sessions. If you process multiple videos in the same session, ALWAYS delete or rename these files before downloading a new video's audio (`rm /tmp/ytaudio.mp3 /tmp/transcript.txt 2>/dev/null`). Failing to do this causes you to transcribe the WRONG video (the previous one). This is a silent error — whisper will succeed and you'll summarize the wrong content. Verified bug: Aug 2026 session produced a stock market summary when asked for a Twitter accounts video.
- **yt-dlp 403 on format 251 (webm audio)**: some videos return HTTP 403 on the default `251` format. Fix: explicitly request format `140` (m4a): `python3.11 -m yt_dlp -f 140 -o '/tmp/ytaudio2.m4a' URL` then convert with `ffmpeg -i /tmp/ytaudio2.m4a /tmp/ytaudio2.mp3 -y -loglevel quiet`. This bypasses the 403 reliably. Check with `yt_dlp -F URL` first if uncertain.
- **Use unique temp filenames per video in multi-video sessions**: use `/tmp/ytaudio2.mp3`, `/tmp/transcript2.txt` etc. for subsequent videos to avoid collisions with earlier files.
- **yt-dlp format 251 (webm/opus) may 403**: if the default format fails, list formats with `-F` and download audio as m4a (format 140) then convert with ffmpeg: `python3.11 -m yt_dlp -f 140 -o '/tmp/audio.m4a' URL && ffmpeg -i /tmp/audio.m4a /tmp/audio.mp3 -y -loglevel quiet`.
- **Dotan watches מיחה מאמריקה** — Hebrew finance/market channel. Same whisper pipeline (small, he, beam_size=1). Videos are typically 18–22 min, two chunks suffice.
- **"Click a button, get a company" / Pulsia-style videos**: these are startup founder story videos, category=Startup+AI, badge-biz + badge-ai.
- **Multiple videos on same topic**: when Dotan sends 2+ videos covering the same topic (e.g. two drone income guides), add a "Comparison with previous video" section to the later pages calling out unique vs. overlapping points. This adds significant value.
- **Transcript-only first**: for English videos where `fetch_transcript.py` succeeds directly (no whisper needed), save the transcript immediately via `> /tmp/vs_git/summaries/transcripts/SLUG.txt` in the same command. No separate copy step needed.
